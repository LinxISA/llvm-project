## 实现范围

新增一个默认关闭的实验选项，先实现“Tile size-aware hand affinity”的最小安全版本，不修改物理寄存器数量、不改变默认分配行为、不尝试删除 ISA 必需的普通 TMOV。

新选项建议命名：

```text
-linxv5-enable-size-aware-tile-hand
```

默认 `false`。它只影响 `Tile_ABSRegClass -> Tile_TR/UR/MR/NR` 的 Clock-Hand coloring；`PseudoTMOV_SizeI`、Shared TMOV、GMOV 和 TRegToOffset 的语义不直接改写。

## 实现设计

### 1. 获取并规范化 Tile size

在 `LinxV5ClockhandsColoring.cpp` 中复用 `LinxV5::getTileOpRegSize(MI, Reg)`：

- 对每个单定义 Tile virtual register，从唯一 def 读取 Tile size code；
- `size == 0`、无法从 inline asm 解析、copy/implicit-def 或多 def 时标记为 Unknown；
- 不把 TableGen register-class 的 `Size=64` 当作 Tile shape/SizeCode；
- 只比较统一后的 size code；不扩展 parser 或 inline asm `%c[N]` size 解析，首版对无法获取尺寸的 inline asm 保守回退普通算法。

在 `RegUnit` 中增加 size bucket/size code 字段，或在 `ColoringInChain` 内维护 `Register -> Optional<unsigned>` side map。首版直接使用 size code 相等性，不硬编码 `Small/Medium/Large/Huge` 边界，避免把 ISA SizeCode 误解为容量单位。

### 2. 建立 hand affinity cost

为候选 `Tile_TR/UR/MR/NR` 计算排序代价：

1. 当前 chain 中已有同 size code 的 live intervals 数量/压力；
2. 当前候选 hand 与 def/use 邻接 Tile virtual registers 的 register class 是否一致；
3. 原有 DUL 作为次级代价；
4. `spillCheck` 仍是硬约束，不得为了 size affinity 强行增加 spill。

建议优先规则：

```text
same-size affinity > same-chain producer/consumer affinity > original DUL order
```

如果候选 hand 会触发 `spillCheck`，直接排除；所有候选失败时回退现有 `finalFastAssign` 的行为。对 Unknown size 的值完全使用旧算法。

### 3. 保留现有 early assignment 语义

首版不改：

- `assignLoopInvar(... Tile_NRRegClass)`；
- `assignAccrosChain(... Tile_MRRegClass/Tile_NRRegClass)`；
- `assignMultiOutput`；
- register class 数量和 physical register enum。

原因是这些阶段直接替换 register class，若同时改动会把 size affinity、loop preference、物理 hand 数量混在一起，难以定位回归。

只在 `ColoringInChain::expertFastAssign` / `finalFastAssign` 的普通 candidate 选择阶段应用 affinity。这样选项关闭时现有代码路径完全不变；选项开启时只改变尚未完成分配的普通 Tile。

### 4. 处理容量

把 size-aware 代码中的压力判断写成候选 RC 自己的：

```cpp
unsigned Capacity = RC->getNumRegs();
```

不新增 16 或 64 常量，也不假设每个 hand 的物理数量。现有 `OneHandRegNum` 继续服务旧算法；size-aware 分支对每个候选类单独取 `getNumRegs()`。

本任务不修改 `LinxV5RegisterInfo.td` 的 16-register 定义，因为用户当前要求是先实现 size-aware 分配实验，物理 hand 扩容是独立工作包。

### 5. 统计和调试输出

增加 `LLVM_DEBUG` 输出（`DEBUG_TYPE=linxv5-clockhands`）：

- register、size code/Unknown；
- 候选 hand 及 affinity cost；
- size-aware assignment/fallback；
- 不输出默认 release build 必需的统计状态。

如可低风险，增加 `STATISTIC`：

```text
SizeAwareAssigned
SizeAwareFallback
SizeAwareUnknownSize
```

不把最终 TMOV 数量作为 allocator 内部统计，因为普通 Local TMOV 与 TRegToOffset 的 `PseudoTCOPY` 是不同概念。

## 测试设计

### 1. 单元/CodeGen 行为

新增或扩展 LinxV5 CodeGen 测试，使用同一输入两条 RUN：

- 默认关闭新选项；
- `-linxv5-enable-size-aware-tile-hand=true`。

优先使用能产生多个 Tile live ranges 的现有测试结构，参考：

- `llvm/test/CodeGen/LinxV5/reuse.ll` 的双 RUN；
- `llvm/test/CodeGen/LinxV5/v5-matmul-tilesize-encode.ll` 的尺寸矩阵；
- `llvm/test/CodeGen/LinxV5/Block-C/multi-output.ll` 的多尺寸输出。

首版不绑定具体物理寄存器编号，优先检查：

- MIR 中 size-aware debug/assignment 信息（若 debug build 可用）；
- 最终 `B.IOT`/tile size 合法性；
- 无新增 `PseudoTCOPY`/spill；
- 默认关闭时原有 CHECK 完全不变。

### 2. TRegToOffset 对比

用现有：

```text
-stats
-debug-only=linxv5-treg-to-offset
```

在相同输入下比较 `NumCopy`。明确区分：

- `PseudoTMOV_SizeI`：真实 Local TMOV 语义；
- `PseudoTCOPY` / `NumCopy`：allocator/TRegToOffset 补偿 copy。

不以“所有反汇编 TMOV 数量下降”作为唯一验收标准。

### 3. 回归测试

至少运行：

- 新增 size-aware CodeGen test；
- 现有 `v5-matmul-tilesize-encode.ll`；
- `v5-shared-register-allocation.ll`；
- `v5-shared-gmov.ll`；
- `Block-C/tile-copy.ll`；
- 相关 LinxV5 MC/CodeGen lit。

必要时用 benchmark ELF 进行 A/B：

```text
size-aware=false
size-aware=true
```

分别统计普通 Local `TMOV`、`PseudoTCOPY`/TRegToOffset copies、spill/reload 和运行结果；不能把 Shared TMOV/GMOV 混入 Local copy 统计。

## 交付边界

本次不做：

- 不修改每个 hand 的物理寄存器数量；
- 不把 16 改成 64；
- 不删除语义上必须存在的 Local TMOV；
- 不实现完整 loop-carried global affinity；
- 不修改 TileOP、ISA 或 benchmark 源码；
- 不提交/推送。

如果首版结果证明仅在极少数 chain 生效，再开后续阶段：

1. loop-carried live-in/live-out hand affinity；
2. early loop-invariant/long-live assignment 的 size-aware 化；
3. inline asm size `%c[N]` 解析；
4. TRegToOffset 与 coloring 的联合 copy-cost 优化。
